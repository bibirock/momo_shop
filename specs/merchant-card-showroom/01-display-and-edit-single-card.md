# P0 Story 1：展示並調整單一商品卡

- 父 Epic：Merchant Card Showroom
- 優先度：P0-1

## 使用者角色（Persona）

- 角色：前端評估者／商品卡設計開發者
- 目標：查看一張接近 momo 搜尋結果的商品卡，並透過調整介面即時確認不同內容及外觀設定。
- 前置狀態：使用者已開啟 Showroom，不需要登入或預先建立資料。

## 背景與動機（Why）

基本需求至少要交付一張可展示及調整的商品卡。本 Story 先建立可獨立 demo 的單卡體驗，作為後續持久化、Sample HTML、多商品與擴充能力的共同基礎。

## In Scope

- 展示一張 search-grid 商品卡。
- 提供以下預設商品 demo-food：

| 欄位 | 預設值 |
| --- | --- |
| 圖片 | mock-food |
| 圖片替代文字 | 日式咖哩調理包商品示意圖 |
| 促銷文案 | 限時優惠 |
| 商品名稱 | 【MOMO精選】日式咖哩調理包 18 入 |
| 售價 | 999 |
| 原價 | 1290 |
| 總銷量 | 總銷量>1,000 |
| 評論數 | 5208 |
| Badges | 速、登記 |
| Accent color | #D71F69 |
| 圓角 | 12px |

- 提供內容及外觀調整介面。
- 合法調整立即反映在預覽，不需要重新整理頁面。
- 提供食品、保健、服飾三種假圖選項。
- 商品圖片可由假圖網站產生；圖片失敗時提供 fallback。
- 桌面與 390px 寬度的窄螢幕皆可完成調整。

## Out of Scope

- Browser-side Persistence、Save、Discard、Reset。
- 多筆商品清單與商品切換。
- Sample HTML、Web Component 或 script embed。
- Dirty state、離頁警告與跨分頁同步。
- Recommendation、History Compact 或其他 variant。
- 真實 momo API、真實線上商品資料及圖片上傳。
- 圖片輪播、收藏狀態、購物車 domain。
- 像素級複製 momo 網站。

## 驗收標準（AC）

AC-01: 顯示預設商品卡
  Given 使用者首次開啟 Showroom
  When 頁面完成載入
  Then 畫面顯示一張 search-grid 商品卡，且呈現 demo-food 的圖片、促銷文案、商品名稱、售價 $999、原價 $1,290、總銷量、評論數 (5,208)、速與登記 badges。

AC-02: 調整介面欄位完整
  Given 預設商品卡已顯示
  When 使用者檢視調整介面
  Then 可找到具可辨識 label 的圖片、圖片替代文字、促銷文案、商品名稱、售價、原價、總銷量、評論數、badges、accent color 與圓角控制項。

AC-03: 合法調整立即反映
  Given 使用者正在調整商品卡
  When 使用者分別變更列舉清單中的任一可編輯欄位
  Then 同一頁面的預覽在不重新載入頁面的情況下反映新值；圖片替代文字可從圖片的可存取名稱觀察，accent color 與圓角可從卡片外觀觀察。

AC-04: 可選內容與長文版面穩定
  Given 使用者清空促銷文案、原價或全部 badges，或輸入超出可視區域的商品名稱
  When 預覽更新
  Then 空白的可選區塊不留下專用佔位文字；商品名稱最多顯示兩行、促銷文案最多顯示一行，超出內容以省略方式呈現，且卡片內容不超出卡片寬度。

AC-05: 窄螢幕與鍵盤操作
  Given viewport 寬度為 390px
  When 使用者只使用鍵盤依序操作所有調整欄位
  Then 預覽與調整介面依序顯示、頁面沒有水平捲動、每個控制項都有可見焦點，且過程沒有 console error 或 uncaught page error。

## 邊界條件

| 維度 | 條件 | 預期行為 |
| --- | --- | --- |
| 空值／缺漏 | 商品名稱為空 | 預覽顯示「未命名商品」；是否允許儲存由 Story 2 判定 |
| 空值／缺漏 | 圖片替代文字為空 | 預覽使用「商品圖片」作為暫時可存取名稱 |
| 空值／缺漏 | 促銷文案、原價或 badges 為空 | 對應可選區塊不顯示 |
| 格式 | 售價、原價或評論數不是非負安全整數 | 不把無效值套用至商品卡；預覽保留該欄位上一個合法值 |
| 格式 | Accent color 不是 #RRGGBB | 不套用無效色彩；預覽保留上一個合法色彩 |
| 上限／規模 | 圓角小於 0 或大於 24 | 不套用無效圓角；預覽保留上一個合法值 |
| 上限／規模 | 商品名稱或促銷文案超出可視空間 | 分別限制兩行與一行顯示，不改寫使用者輸入內容 |
| 上限／規模 | 商品與選項數量 | 本 Story 僅一筆商品、三種圖片選項及四種 badge |
| 錯誤路徑 | 假圖載入失敗或遠端服務不可用 | 顯示不破版的圖片 fallback 與有效替代文字，調整介面仍可操作 |
| 權限／角色 | 未登入使用者開啟 Showroom | 可直接查看及調整，不要求帳號或權限 |

## 驗收場景

1. 使用者開啟 Showroom，看見預設商品卡，依序修改商品圖片、文字、價格、badges、色彩及圓角，並立即看到合法設定反映在預覽。
2. 使用者輸入過長文字、清空可選內容或遇到圖片載入失敗，商品卡保持可辨識且調整流程不中斷。
3. 使用者在 390px viewport 以鍵盤完成欄位調整，頁面沒有水平溢出或瀏覽器錯誤。

## 預估開發點數（Story Points）

- 點數：8
- 維度理由：實作面需建立完整商品卡、調整介面及響應式頁面，約為單一元件錨點的 2–3 倍；狀態與契約需定義單卡設定及即時 draft；整合面僅包含假圖來源與失敗 fallback，無後端整合；驗證工作量包含全部欄位、長文、圖片失敗、鍵盤與窄螢幕 E2E。
- 拆卡判定：已由 Epic 依 Paths／Interfaces 垂直拆出；本 Story 只有「展示並即時調整單一卡片」一個可獨立 demo 的目標，8 點且不需再拆。
